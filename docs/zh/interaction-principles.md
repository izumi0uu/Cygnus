# Support Brain for SaaS — 交互原则

## 1. 主交互姿态：Coordinate and Command
这套产品最核心的交互感觉不是：
- approve AI suggestion
- triage 一条条局部问题
- investigate 一个对象然后结束

而是：
**support lead 站在一个控制层上，对多个队列、团队、知识对象和渠道发出协调动作。**

这意味着系统需要让用户感到：
- 我不是只在看告警
- 我不是只在看证据
- 我正在改变支持系统接下来怎么运转

## 2. 交互的五级阶梯

### Level 1：Notice movement
系统先让用户看见哪里发生了变化。

### Level 2：Interpret relevance
系统帮助用户判断这件变化为什么重要、影响谁、值不值得动。

### Level 3：Choose intervention
用户决定：
- 路由给谁
- 先修什么
- 限制什么发布
- 升级哪条路径

### Level 4：Issue command
用户明确发出协调动作。

### Level 5：Confirm propagation
系统必须回显：
- 哪些对象被影响
- 哪些团队被波及
- 哪些 surface 已经同步
- 哪些地方仍未闭合

## 3. 顶层交互原则

### 原则 A：先系统，后对象
默认入口应该先呈现系统 movement，而不是对象目录。

### 原则 B：先协调，后编辑
如果用户的真正任务是“改变系统的优先级或路由”，系统不应逼他先进入繁琐编辑。

### 原则 C：每个动作都要有作用范围
任何 command 都要回答：
- 会影响什么对象
- 会影响哪些 audience
- 会影响哪些下游 surface
- 会影响谁的工作顺序

### 原则 D：支持局部 drill-down，但不能失去指挥姿态
用户可以进入深层证据，但系统不能让他在局部里忘记自己原本是在指挥全局。

### 原则 E：supporting surfaces 只能接收主系统节奏
copilot、frontline surface、external answer surface 的交互不应反过来定义 control tower 的节奏。

## 4. 行动层级
在完整体验里，动作应自然形成层级：

### 第一层：判断动作
- 标记优先级
- 确认影响范围
- 识别负责人

### 第二层：协调动作
- 路由
- 分配
- 升级
- 改变处理顺序

### 第三层：治理动作
- 发起审阅
- 调整 audience variant
- 改变 publish 可见性
- 要求证据补齐

### 第四层：验证动作
- 查看传播结果
- 查看重写是否下降
- 查看 drift 是否收敛

## 5. Command 不应像什么
一个 command 不应像：
- 点一个按钮然后系统自己消失处理
- 批准一条 AI 建议然后结束
- 跳转到另一个页面后失去上下文

一个 command 应该像：
- 明确的系统动作
- 清楚的作用范围
- 可追溯的责任与后果
- 可以被后续观察验证

## 6. Drill-down 的交互边界
Drill-down 很重要，但只是第二层。

它的作用是：
- 解释为什么问题值得动
- 解释为什么这个 audience 会受影响
- 解释为什么当前对象会成为风险中心

它不应把主叙事改写成：
“这是一个内容编辑产品。”

## 7. 冲突与未闭合状态
这类系统最大的价值，往往来自于它敢于暴露未闭合状态。

因此交互应允许用户清楚感知：
- 这个动作还没有完全传播
- 这个对象还在和别的规则冲突
- 这个 source 还不可靠
- 这个队列仍然缺 owner

不要为了“流畅”而隐藏冲突。

## 8. supporting surfaces 的交互定位

### Copilot surface
它的主要交互意义是回报：
- 哪些知识真的被采用
- 哪些知识仍被人工纠偏
- 哪些建议应重新上升到 control tower

### External answer surface
它的意义是传播结果，而不是主互动场。

## 9. 交互反馈原则
好的反馈不只是说“成功”。
它应该告诉用户：
- 你的动作改变了什么
- 谁会最先受到影响
- 哪些地方已经同步
- 哪些地方仍需进一步动作

## 10. 完整体验中的危险误区
如果交互开始给用户以下感觉，就说明偏了：
- “我主要在审批 AI”
- “我主要在翻证据”
- “我主要在修一篇文章”
- “我主要在处理工单”

它应该给人的感觉是：
- “我在重新编排支持系统的动作顺序”
- “我在决定哪个问题先被整个组织处理”
- “我在让下游回答系统重新同步”

## 11. 交互检验问题
任何关键动作都应回答：
- 这是观察动作，还是协调动作，还是治理动作？
- 用户是否知道它的作用范围？
- 用户是否知道动作之后会去哪里、影响谁？
- 系统是否让用户看到了传播结果，而不是只看到了动作完成？
